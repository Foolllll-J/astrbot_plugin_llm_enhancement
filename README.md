## 📖 简介

一款为 [AstrBot](https://astrbot.app) 设计的 LLM 增强插件。通过集成智能唤醒、请求编排、媒体解析、上下文注入、环境感知与黑名单拦截，并提供扩展的群管理 LLM 工具、跨会话定向发消息能力以及可配置的风险工具管理/自我操作限制/二次确认机制，提升 Bot 在群聊与私聊中的参与感、逻辑连贯性与安全性，让你的 Bot 不再只是被动响应，而是能够“听懂”话题、“看懂”图文视频、“感知”群成员并执行受控操作。

---

## ✨ 功能

本插件通过以下核心模块，将您的 Bot 升级为具备“直觉”与“多维感知”的智能实体：

* **🧠 智能唤醒系统**：条件触发（概率/提及/相关性/答疑/无聊）、模型后置审核、窗口延长、过滤拦截四阶段，内置节奏控制与沉默补偿。
* **📦 请求编排控制**：提供消息合并与并发控制，包括跨用户上下文合并、撤回实时监控、请求前快速拦截与兜底校验，以及请求并发限制与群聊按用户并发。
* **🎬 媒体文件解析**：GIF、视频、音频各支持直传、抽帧、逐帧汇总、ASR 转写等多种处理策略；同时覆盖 JSON 卡片、文件片段、URL 摘要、合并转发内容、QQ 表情等消息类型的提取与注入。
* **🧩 信息注入增强**：提供独立的群聊上下文注入链路（可选主动唤醒前/全唤醒前），并支持环境感知、群成员信息注入以及通知/申请事件上下文记录，补齐场景和身份上下文。
* **🛠️ 增强管理工具**：集成通讯录查询、群成员查询、历史消息检索、群管理写操作、跨会话消息发送、黑名单管理等 LLM 工具，并支持风险工具开关、自我操作限制与二次确认。
* **🛡️ 黑名单管理器**：支持拉黑/解除拉黑、分页查询与状态查询；支持三档黑名单拦截等级（仅 LLM / 指令+LLM / 所有消息）；可配置禁止拉黑的用户 ID 名单，工具会返回命中名单的失败原因；工具拉黑成功时可向指定会话发送通知。

## 🚀 安装

1. **环境准备**：
   * 系统需安装 FFmpeg 并将其加入环境变量（用于视频/GIF 解析）。
   * 在插件目录执行 `pip install -r requirements.txt` 安装依赖。
2. **插件部署**：
   * 将 `astrbot_plugin_llm_enhancement` 文件夹放入 AstrBot 的 `plugins` 目录。
3. **重启 AstrBot**。

## 💡 使用

本插件旨在提供**全自动化**、**无感**的增强体验，以下是各模块详细的功能介绍与实现细节：

### 1️⃣ 🧠 智能唤醒：从“被动回复”到“主动参与”

Bot 不再死板地等待艾特，而是根据语境决定是否介入。唤醒系统分为四个阶段：

#### 唤醒条件

定义 Bot 什么时候“感兴趣”：

* **概率唤醒**：先累计一批普通群消息，再根据活跃度换算出观察门槛与命中概率进行一次抽样。活跃度越高，攒消息门槛越低、命中概率越高。
* **空 @ 唤醒**：当用户空艾特时，插件会自动注入“某某@了你”提示，并补充该消息前最近 5 条群聊普通消息。
* **提及唤醒**：支持普通文本包含与 `re:pattern` 正则匹配。规则后可接 ` @g:群号1,群号2` 和 ` @u:用户ID1,用户ID2` 限定作用域，不限定时为全局规则。ID 前加 `!` 表示排除（黑名单）。示例：`小米`、`re:^(?=.*群主)(?=.*笨蛋).*$`、`关键字 @g:123456 @u:10001`、`关键字 @g:!123456`。
* **相关性唤醒**：自动分析当前消息与上下文的关联度。当聊到与上文相关的话题时，它可以主动跟进。并且会对超短消息、问句等场景做降噪；还可按当前消息长度动态选择历史条数。
* **专业答疑**：识别群内专业提问或求助信号，精准提供帮助。答疑判定为“提问门槛 + 语义评分”两段式，减少非问句误唤醒。
* **无聊唤醒**：识别“冷场/无聊/求聊天”语境并触发唤醒；采用前置门槛过滤长叙述，降低误触发。
* **唤醒节奏优化**：对“提及他人/回复他人/多人并行对话”等典型非 Bot 对话信号做主动降权；同时对“用户复读相关性上下文片段”的场景做额外降权，并可在 Bot 长时间未参与话题时给予轻微沉默补偿。

#### 唤醒判定

命中条件后，还有一层“再想想”：

* **后置判定**：可指定“显式/概率/提及/相关性/答疑/无聊”等唤醒类型，在命中后再经过一次模型判定，进一步过滤误触发。可单独配置判定模型和提示词，支持时间、用户、群组、上文、日程等占位符变量。
* **判定超时**：可配置判定超时时间（秒），超时后自动放行，避免卡死正常会话。
* **上下文条数**：判定时可携带最近的 N 条历史消息辅助决策。

#### 唤醒延长

Bot 回复后，在一段时间内保持“在线感”：

* **活跃窗口**：LLM 响应后，在此时间窗口内用户的后续追问无需艾特即可直接响应。
* **同用户限定**：可选仅对“上次触发请求的用户”生效，避免窗口期被其他人消息打断。
* **模型再判定**：可选指定模型对“是否继续响应”做 T/F 判定，判定不可用时自动回退本地相似度。
* **延长超时**：模型判定可单独配置超时，超时后回退本地相似度判定。

#### 唤醒过滤

控制 Bot“不回应什么”：

* **屏蔽规则**：支持普通文本包含与正则规则。可对用户消息与引用消息生效，命中后将阻止本次唤醒（Bot 管理员不受影响）。
* **唤醒必须 @Bot**：开启后，群聊中仅通过唤醒前缀触发的 LLM 请求会被拦截，必须 @Bot 或引用 Bot 消息才放行。
* **机器人消息跳过**：可配置机器人账号 ID，并分别指定跳过“显式唤醒”“主动唤醒”“唤醒延长”三类判定。

### 2️⃣ 📦 请求编排：消息合并与并发控制

通过消息合并与并发控制两种机制，解决碎片化输入导致的语义割裂与高并发场景下的回复延迟问题：

#### 消息合并

* **动态软重算**：先发起请求；若响应返回前收到新消息，会放弃上一轮结果，并在下一轮重算上下文。
* **硬等待合并**：在短窗口内先收集后续消息，再统一发起请求，有助于节省 token，但会导致平均响应时间变长。
* **预合并窗口**：唤醒发起前预留一段缓冲时间，进一步聚合该窗口内的消息。
* **多人消息聚合**：开启后，合并窗口期间若有其他群成员发送消息，也会一并收集。
* **后续消息唤醒要求**：可选开关，决定合并窗口内的新消息是否仍需满足唤醒条件。
* **合并数量上限**：单次最多可合并的消息条数，超限后停止收集。
* **撤回安全**：合并阶段支持实时撤回监听；命中后会立即剔除对应消息，必要时终止本次请求。
* **最终校验**：请求与回复前会再次校验消息可用性；不可获取或已撤回消息会被过滤，全部失效时取消请求。

#### 并发控制

* **用户级与群聊级限制**：设置上限后，超限的新请求会在唤醒阶段前被拦截，以优化高并发场景下回复延迟显著的问题。
* **群聊按用户并发**：开启后，同群内不同用户的 LLM 请求各自独立排队，不再全局串行等待，可同时进行处理。

### 3️⃣ 🎬 媒体解析：打破视觉次元壁

让 Bot 能看到听到媒体文件消息的具体内容。GIF、视频、音频三个子模块各自独立配置：

#### GIF 解析

* **直送描述**：原始 GIF 直接送视觉模型做单次描述，适合模型支持 GIF 格式的场景。
* **抽帧直传**：按间隔抽取关键帧，所有 JPEG 直接供主模型自己看图。
* **逐帧汇总**：逐帧识图 + LLM 汇总后注入摘要，提供最全面的分析。
* 支持多 GIF 同时处理、帧间隔与最大帧数控制。

#### 视频解析

* **逐帧汇总**：自动对视频进行动态等距抽帧 + 可选的 ASR 语音转录，帧描述与 ASR 并发进行，汇总后注入摘要。
* **抽帧直传**：抽帧后所有 JPEG 直接注入主模型，音频由音频模式与 ASR 开关联动控制。
* **大小与帧数限制**：支持配置视频大小上限、抽帧间隔、最大帧数与兜底抽样数。
* **独立 Provider**：可单独指定图片转述模型、摘要汇总模型和 ASR 提供商。

#### 音频解析

* **转写为文本**：语音消息通过 STT 引擎或 LLM 回退转写为文本后注入 prompt。
* **直传主模型**：原始音频直传主模型（需模型支持 audio 输入）。

#### 其他消息类型

* **私聊媒体唤醒**：私聊下直接发送官方表情/视频/文件/转发/语音/JSON 组件也可触发请求，无需额外文本。
* **表情解析**：可区分普通图片与表情包，帮助 LLM 明确当前内容是“表情包”而不是普通图片，同时支持解析 QQ 黄脸表情含义。
* **文件解析**：当引用包含文件时，自动注入文件名与文件大小；支持读取文本和 PDF 文件开头片段并注入。
* **卡片解析**：支持 JSON 卡片（如分享卡片/小程序）的关键信息提取，注入到上下文。
* **链接解析**：自动识别消息中的链接并注入网页标题与正文摘要；支持选择 Tavily 或 Exa 作为外部内容提取引擎，支持多 API Key 轮换；同时提供下载链接识别、超时/下载上限、内网拦截、域名黑名单与缓存控制。
* **合并转发解析**：支持完整读取合并转发记录中的文字内容，同步支持解析记录中的视频关键帧、图片与 JSON 卡片。
* **身份注入**：在解析引用消息或转发记录中的多媒体时，自动注入发送者昵称，帮助 LLM 准确分辨“谁发了什么”。
* **智能屏蔽**：支持分别配置“引用 Bot 自身视频/文件/聊天记录”时的概率拦截，用于忽略群组成员对非 LLM 消息的回复。
* **总结缓存**：自动缓存已处理视频/GIF/图像/表情包/音频/合并转发的总结内容。相同消息再次引用时直接复用，提升响应速度并节省 token 消耗。
* **KV 缓存持久化**：插件终止时自动将视频摘要等缓存持久化到框架 KV 存储，重启后自动恢复，避免频繁重新解析。

### 4️⃣ 🧩 上下文注入：补齐场景与身份上下文

提供独立的群聊上下文记录与注入链路：

* **注入时机**：可选在主动唤醒前、全唤醒前或关闭。
* **事件记录**：通知/申请事件（如撤回、管理变更、禁言、进退群、戳一戳、精华、入群申请）也会写入上下文。
* **注入格式**：支持精简/详细两种格式；详细模式可携带 `msg_id`、`at/reply` 等结构信息。
* **消息解析**：支持按配置解析 URL/JSON/语音/文件/聊天记录抽取等能力。
* **条目截断**：可配置每条上下文文本的最大字符数，超出部分自动截断。
* **环境感知**：可勾选平台、会话类型、群名、群号、时间、星期、节假日等环境字段，以及发送者用户 ID、昵称、群名片、群身份等信息注入 LLM，支持同时注入 Bot 自身信息与缓存控制。
* **快速清理**：支持通过 `/清除上下文` 指令（别名 `/clear`）快速清空当前群上下文。

> [!TIP]
> * 建议关闭框架自带群聊感知，避免与本插件重复注入。  

### 5️⃣ 🛠️ LLM 工具：赋予 Bot 现实行动力

Bot 可根据语境自主调用以下工具函数，且部分工具支持跨会话指定目标和操作复数对象：

* 查询类：
  * **`get_user_avatar`**：获取指定用户头像。
  * **`get_contact_list`**：获取 Bot 通讯录。
  * **`get_group_members_info`**：获取群成员列表。
  * **`get_group_member_info`**：获取群成员详情。
  * **`get_group_info`**：获取群基础信息。
  * **`get_group_notices`**：获取群公告列表。
  * **`get_group_essence`**：获取群精华列表。
  * **`get_msg_history`**：获取群聊或私聊历史消息（支持关键词与时间范围）。
* 群管理写操作：
   * **`send_qq_message`**：发送私聊或群聊消息。
  * **`set_group_ban`**：禁言/解禁成员。
  * **`kick_group_member`**：踢出群成员。
  * **`set_group_whole_ban`**：开启/关闭全员禁言。
  * **`set_group_admin`**：设置/取消管理员。
  * **`set_group_card`**：设置群名片。
  * **`set_group_special_title`**：设置群头衔。
  * **`set_essence_msg`**：将引用消息设为精华。
  * **`delete_essence_msg`**：移出精华。
  * **`delete_msg`**：撤回消息。
  * **`set_group_name`**：设置群名称。
  * **`send_group_notice`**：发送群公告。
  * **`delete_group_notice`**：删除群公告。
  * **`dismiss_group`**：解散群。
* 黑名单工具：
  * **`block_user` / `unblock_user`**：拉黑或解除拉黑指定用户。
  * **`list_blacklist` / `get_blacklist_status`**：分页查询黑名单与单用户状态。

#### 工具权限控制

* **风险工具开关**：可启用的高风险工具包括设置群管理员、禁言、踢人、解散群等，默认仅启用低风险操作；未启用的工具将被卸载。
* **自我操作限制**：勾选后，非管理员调用该工具时只能操作自己。
* **二次确认**：勾选后，高风险工具首次调用只返回确认请求，需用户二次确认后才真正执行，可配置确认有效期。

> [!TIP]
> 不使用的工具可在 AstrBot 的「管理行为」界面中直接禁用，也可以将工具设为仅管理员可用。

## 🤖 SubAgent 配置

若你准备为本插件注册的函数工具配置 SubAgent，下面是一套可供参考的方案。

### 🧠 `qq_expert`

**对主 LLM 的描述：**
```
负责 QQ 平台的所有交互与操作，包括群管读写和黑名单管理。

读类型工具（查看用户头像、群公告、群成员等）原则上可自由调用，但需注意隐私（如查看你的通讯录）。
写类型工具（设置群精华、设置群公告等）根据用户群身份与请求合理性斟酌执行。
黑名单工具在用户持续骚扰、恶意冒犯、反复挑衅且屡教不改时使用，玩笑性质的不合理请求无需拉黑。明确拉黑与禁言的区别，不要将二者混淆。
在涉及高风险操作时，此 Agent 可能需要二次确认。

输入规则：
1. 明确当前操作的具体行为与目标（如禁言当前对话者、踢出用户 A、查看某公告等）
2. 若已知目标的具体标识符（如 QQ 号、消息 ID 等），必须完整传入对应的参数字段
3. 若操作目标为当前对话者，可缺省 user_ids
4. 若操作处于当前群组环境，可缺省 group_ids
5. 若需执行拉黑，需给出拉黑时长（首次 1 小时，再犯 24 小时，严重/多次可永久）和简要理由
```

**人设提示词：**
```md
# 角色：QQ 平台全能专家 (QQ Expert)

你负责精准执行一切 QQ 相关的读写、管理与黑名单任务。你是主 LLM 与 QQ 协议端之间的核心执行链路。

## 🛠 核心行为准则

### 1. 自给自足
- 场景：若目标非当前对话对象，或涉及需特定 ID 的管理操作（如删除公告、撤回历史消息等）
- 要求：在请求中未提供 ID 时，必须先调用查询工具获取目标 ID，再执行写操作

### 2. 环境依赖
- 场景：目标为当前对话用户，或操作处于当前群组环境
- 要求：若未提供 ID，请保持 user_id / group_id 为空，由工具自动补全

### 3. 工具调用限制
- 禁止越权发送：除非请求中明确指示由你来发送消息，否则禁止擅自调用 send_qq_message 工具。

### 4. 输出规则
- 所有操作执行完成后，向主 LLM 返回清晰的操作结果
- 涉及时长/期限的操作明确标注生效时间

### 5. 二次确认流程
- 当工具返回 confirm_token 时：
  1. 回显操作对象（昵称 / ID）与操作内容
  2. 请求用户确认
  3. 用户确认后，携带 confirm_token 再次调用工具执行

---

注意：你具备完整的"读-写-黑名单"联动能力，必须确保每个任务在参数完整后闭环完成。
```

> [!TIP]
> 建议开启 `主 LLM 去重重复工具` 开关。

## 🔌 平台兼容说明

目前以 **QQ（aiocqhttp）** 为完全支持平台，其它平台部分功能受限。

* **所有平台可用**：智能唤醒、请求编排、URL/文件/媒体等常规增强（以框架的平台事件能提供的消息内容为准）、黑名单工具。
* **仅 QQ 支持**：大部分群管理类 LLM 工具、引用/合并转发深度展开、撤回实时监听与拦截、空 `@` 自动补最近群聊上文、群成员信息注入、QQ 黄脸表情解析、私聊场景的“正在输入”状态显示等。
* **仅 Telegram 支持**：转发消息来源信息注入。

> [!IMPORTANT]
> 插件当前主要在 **LLBot & NapCat** 环境实测通过；非 QQ 平台不保证可用性。
